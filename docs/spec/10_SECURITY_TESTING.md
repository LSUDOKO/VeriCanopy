# 10 · Security, Threat Model and Testing

## 1. Assets to protect
Integrity of scores, exclusivity of land claims, credit supply accounting, oracle/resolver keys, PQ signing key, user funds (stakes/bonds), and the honesty of public claims.

## 2. Threat model (STRIDE-style)

| # | Threat | Attack | Mitigation |
|---|---|---|---|
| T1 | Oracle swaps model | Uses a friendlier model off-chain | zk proof bound to registered model's verifier; `ModelRegistry` governance |
| T2 | Oracle fakes score | Submits score ≠ model output | Score decoded from proof instances |
| T3 | Oracle manipulates inputs | Wrong dates, cherry-picked cloudy scenes, shifted geometry, biased twin sampling | Manifest with all parameters + seeds; geometry hash checked vs registry; open challenges with slashing |
| T4 | Proof replay | Reuses an old valid proof for another project/period | Period monotonicity; manifestHash binding; P1: projectId/period as public inputs |
| T5 | Double registration | Same land in two projects | H3 Tier-1 lock + Tier-2 Merkle overlap fraud proof |
| T6 | Sliver overlaps | Overlap smaller than a res-8 cell | Tier-2 fine-cell fraud proof |
| T7 | Challenge griefing | Spam challenges to delay finalisation | Bond ≥ half the oracle stake; losing bond is split to oracle |
| T8 | Resolver collusion/censorship | Resolvers never vote or vote dishonestly | Timeout voids (no forced outcome); independent operators; roadmap: decentralised resolver staking (see research D1–D4) |
| T9 | Key theft | Oracle ECDSA or ML-DSA key stolen | Secrets manager, key rotation via registries, minimal hot balances |
| T10 | Quantum forgery of history | Future forging of ECDSA records | Hybrid ML-DSA signatures on manifests (see `07`) |
| T11 | Reentrancy / payout bugs | Draining stakes | Pull payments, `nonReentrant`, invariant tests |
| T12 | Frozen credits laundered | Transfer/retire tokens of a frozen project | `_update` override blocks movement; tests |
| T13 | Data-source tampering | Compromised API responses | Pin dataset versions; cross-check two sources for reversal confirmation (Hansen vs DW+S1) |
| T14 | Web front-end spoofing | Fake UI shows fake "verified" | Verify page re-checks everything from chain + IPFS; publish contract addresses in README |
| T15 | Defamation / misinformation | Labelling a real project fraudulent | Demo projects only; "model estimate" labels; cite peer-reviewed evaluations |

## 3. Test plan

### Contracts (Foundry)
- Unit tests per function (see `06` §11), including all revert paths and role checks.
- Fuzz tests: random cell sets for overlap logic; random challenge sequences.
- Invariants: `issued == circulating + retired + bufferHeld + buffer burned + other burned`; frozen project tokens never move; sum of pending withdrawals ≤ contract balance.
- Real EZKL fixture: a proof generated by `ai/zk` committed as test data; one test with a tampered instance must fail.
- Static analysis: Slither (CI, fail on high severity).

### AI pipeline (pytest)
- Formula unit tests with hand-computed values.
- Determinism test: run twice from a manifest → identical features and score.
- Monotonicity tests on the trained model.
- Float vs proven-output error test across ≥1,000 vectors.
- Regression snapshot for the 3 demo projects (features + score stored in `tests/snapshots`).

### PQ module
- Sign/verify round trip; tampered manifest fails; wrong key fails; canonicalisation stable across key order.

### Backend
- API tests with a test database; indexer tests with a local Anvil chain replaying events, including a reorg simulation.

### Frontend
- Component tests for badges and error decoding; Playwright end-to-end: register → overlap rejection → view project → verify page → demo slider.

### End-to-end (local)
`make e2e`: Anvil chain + deploy + run pipeline on Demo Project A + submit + finalise + mint + retire + reversal on Demo Project C + challenge flow.

## 4. Pre-launch (production) requirements
- Independent smart contract audit; bug bounty.
- Methodology peer review (scientific advisory group).
- Pen test of API and infra.
- Incident response plan, pause runbook, key rotation runbook.
