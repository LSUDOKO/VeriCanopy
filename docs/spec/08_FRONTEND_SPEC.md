# 08 · Frontend Specification (Next.js web app)

## 1. Design direction
- Feel: scientific instrument meets trustworthy registry. Calm, precise, evidence-first.
- Palette (CSS variables, light + dark): deep forest green `#0F3D2E`, canopy green `#2E7D4F`, verified teal `#14B8A6`, warning amber `#F59E0B`, impaired red `#DC2626`, neutral slate greys. Status colours must also have text labels and icons (not colour alone).
- Type: Inter (UI), JetBrains Mono (hashes, CIDs, numbers).
- Mobile responsive; map pages usable at 375 px width.
- Accessibility: WCAG AA contrast, keyboard navigation, aria labels on map controls.

## 2. Global elements
- Top bar: logo, nav (Explore, Register, Portfolio, Challenges, Verify, Security, Demo), network badge (testnet name), RainbowKit connect button.
- Integrity badge component: `score (0–100) · status` with colour + icon: Active ✓, UnderReview ⏳, Impaired ⚠, Frozen ⛔.
- Proof badge: "Proof verified on-chain ✓" (link to explorer tx) or "Verified off-chain" (fallback mode).
- Hash/CID chip: truncated mono text, copy button, link to IPFS gateway or explorer.

## 3. Pages

### `/`: Explore (map home)
- Full-width MapLibre map; project polygons coloured by status; H3 cell overlay toggle.
- Left panel: searchable list of projects with integrity badges; filters (status, score range, country).
- Headline stats from the indexer: projects, credits issued, credits retired, tonnes reversed and covered by buffers. Show `—` if no data.

### `/projects/[id]`: Project detail
- Header: name, developer, area, start date, status, integrity badge, proof badge.
- Tabs:
  1. **Evidence**: map with project polygon and twin sample areas; Sentinel-2 before/after slider; chart: forest cover over time (project vs matched twins with CI band); fire events.
  2. **Integrity history**: line chart of `scoreBps` per period; table of submissions (period, score, reversal, model hash, manifest CID, tx, challenge status).
  3. **Claim vs reality** (P1 F8): claimed baseline vs observed; extracted PDD claims with page refs; "model estimate" label.
  4. **Credits**: vintages, issued, buffer, retired, available; buy (demo) and retire buttons.
  5. **Proofs and signatures**: model hash, verifier address, feature commitment, manifest viewer (pretty JSON), ML-DSA verify button.
  6. **Challenges**: open challenges, history; "Challenge this score" button (opens modal: reason, evidence upload → IPFS, bond amount).

### `/register`: Register a project
- Step 1: draw/upload polygon (GeoJSON/KML). Show area, H3 cells preview (res 8).
- Step 2: live overlap pre-check (API reads `cellOwner` via indexer); red highlight of conflicts with the existing project's name.
- Step 3: metadata (name, start date, claimed baseline, PDD upload).
- Step 4: transactions: `createProject` → `addCells` (batched, progress bar) → submitted for activation.
- If an overlap exists the on-chain call is still attempted only if the user insists, to demonstrate the revert in the demo; show the decoded custom error.

### `/portfolio`
- Holdings per token with live integrity; retirements with "score at retirement" vs "score now"; impact notices inbox (from backend notifications); certificate download.

### `/challenges`
- All open challenges with countdowns; resolver vote status; history with outcomes and payouts.

### `/verify`
- Select a submission or paste a manifest CID → run checks: manifest hash matches chain ✓, PQ key registered ✓, ML-DSA signature valid ✓, zk proof verified (tx link) ✓. Each check shows pass/fail with explanation.

### `/security`
- Trust model table and PQ scope table (from `03` §3 and `07` §7). ECDSA vs ML-DSA measured comparison card.

### `/demo`: guided demo (hackathon)
- Stepper with 5 steps matching the video script (`12_HACKATHON_SUBMISSION.md`).
- Time slider (2018→2025) driving project states from precomputed real outputs; at the fire year: score drops, buffer burn animation, notification toast.
- Banner: "Replay of real pipeline outputs on testnet data".

## 4. Web3 integration
- `wagmi` + `viem`; contract addresses and ABIs from `deployments/<chainId>.json` generated by the deploy script.
- Decode custom errors and show human messages (`OverlapDetected` → "This land overlaps Project #… at cell …").
- Wait for confirmations; optimistic UI only after tx receipt.
- Read heavy data (lists, history) from the backend API; read critical single values (score, status) directly from chain for trust.

## 5. Components list
`MapView`, `H3Overlay`, `ProjectList`, `IntegrityBadge`, `ProofBadge`, `HashChip`, `TwinChart`, `BeforeAfterSlider`, `ScoreHistoryChart`, `SubmissionTable`, `ChallengeModal`, `RetireModal`, `ManifestViewer`, `VerifyChecklist`, `PQComparisonCard`, `DemoStepper`, `TimeSlider`, `NotificationInbox`.

## 6. Empty, loading, error states
Every data component has skeleton loading, a clear empty state, and an error state with retry. Never show placeholder numbers that look real.
