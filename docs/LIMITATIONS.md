# Limitations (honest scope)

This file lists every place where the MVP deviates from the full specification in `docs/spec/`, and why. Updated as the build progresses.

| Area | Limitation | Reason | Path forward |
|---|---|---|---|
| Earth Engine | Live satellite extraction runs only when `EE_SERVICE_ACCOUNT_JSON` is set. Otherwise the pipeline runs on committed **fixture samples** (`data/demo/samples/`) and every output is labelled `provider: fixture`. | No Earth Engine credentials in the build environment. | Set credentials; `make pipeline` then uses `EarthEngineProvider`. |
| Post-quantum library | ML-DSA-65 is implemented with `dilithium-py` (pure Python, FIPS 204) rather than liboqs. | No C toolchain dependency; same algorithm and parameter set. | `pip install -e "./ai[oqs]"` switches to liboqs via the same interface. |
| Database | SQLite by default; Postgres via `DATABASE_URL`. PostGIS is not required because overlap pre-checks use H3 in Python. | Lean local dev. | Postgres/PostGIS in `docker-compose.yml`. |
| IPFS | Content-addressed local store with real CIDv1 (raw, sha2-256). Mirrored to a kubo node only when `IPFS_API_URL` is set. | No pinning service in dev. | Pinning service in production. |
| Post-quantum scope | Only manifest attestations are PQ-signed. Halo2/KZG proofs and Ethereum ECDSA are **not** quantum-safe. | Technology availability. | See `docs/spec/07_POST_QUANTUM.md` §8. |
| Challenge resolution | 2-of-3 resolver multisig (trusted operators). | MVP. | Decentralised staked resolvers (roadmap). |
| Model | v1 scorer is distilled from a transparent expert rule; zkML proves the published model was used, not that the rule is right. | No labelled dataset at MVP stage. | Backtest against published REDD+ evaluations. |
| zk fixed point | Inputs/params use scale 2^9; measured max score error vs float is in `docs/BENCHMARKS.md` (≈6 bps on the demo vector). The lookup range is pinned to the measured logit domain [-12, 4] rather than EZKL's calibration. | At scale 13 the sigmoid lookup needs 2^18 rows; calibration's narrow range made the prover hang on valid inputs. | Larger log-rows on a bigger prover machine. |
| Verifier build | `Halo2Verifier.sol` is compiled with plain solc (no via-IR) by `scripts/compile_verifier.py` and deployed by `scripts/deploy_verifier.py`, not by Foundry. | EZKL's hand-written Yul does not compile under via-IR, which the rest of the project needs. | Keep the two-step deploy; documented in `make deploy`. |
| Proof replay | `projectId`/`period` are **not** public inputs of the circuit and `manifestHash` is not checked on-chain. On-chain, only period monotonicity and the oracle role limit reuse of a proof; the manifest's project/period are checked off-chain by the Verify service and by challengers recomputing the manifest. | Model v1 circuit. | Model v2 with projectId/period as public inputs (roadmap). |
| Testnet | Not yet deployed to Polygon Amoy; everything runs on a local Anvil chain. | No funded deployer key in the build environment. | `RPC_URL=… DEPLOYER_KEY=… make deploy`, then `make seed`. |
| Evidence tiles | Sentinel-2 before/after tiles are not shown. | Needs Earth Engine tile URLs. | Enabled with credentials in a follow-up. |
| Pre-issuance reversals | A reversal before any vintage exists records a shortfall but does not freeze the project; `mintVintage` reverts with `OutstandingShortfall` while any shortfall is outstanding, so the debt cannot be bypassed. | Nothing to protect yet; freezing would block first issuance. | Governance clears the shortfall (e.g. shared pool) before issuance. |
| Browser PQ verification | ML-DSA verification runs in the backend (`POST /verify/pq`), not in-browser WASM. | P1 per spec. | WASM build. |
| Playwright e2e | Browser end-to-end tests are not included; unit tests (vitest) + `next build`/lint run in CI, and `scripts/e2e.py` covers the protocol end to end. | Time. | Add Playwright against a preview deployment. |
| Rate limiting | `slowapi` middleware enforces a global 240 req/min per IP; no per-route tuning. | MVP. | Per-route limits + API keys for the public API. |
| Mock verifier mode | When no `Halo2Verifier` is compiled (or `ZK_MODE=offchain`), submissions carry **no zk proof**; the UI shows "No zk proof (mock verifier fallback)" and `zk_proof_verified=false`. The deploy script refuses a mock on any chain other than 31337 unless `USE_MOCK_VERIFIER=true`. | Documented fallback (05 §6). | Always deploy the real verifier (default `make deploy`). |
| Web registration | Projects registered from the browser commit a placeholder `fineCellRoot`, so Tier-2 sliver fraud proofs are not available for them (demo seed projects have real roots). | Res-11 polyfill is too heavy for the browser. | Compute the root server-side in the overlap pre-check. |
